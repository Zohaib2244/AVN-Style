One UX, any style

Flip Style at the top between AVN Family and Nutstyle classic. Every screen below changes its look; nothing moves, disappears or behaves differently. That is the contract.

The UX decides (stays forever)

  • What is on each page, in what order, and the page patterns.
  • How things behave: navigation, pickers, drawers, rules, undo, loading, errors, toasts.
  • The words: labels, messages, empty states.
  • Breakpoints, density, touch sizes, keyboard support.
  • Which role something has: primary action, status kind, highlight colour 1–6.

A style decides (swap any time)

  • Colours for every role: surfaces, text, accent, status kinds, the 6 highlight colours, both themes, any palettes.
  • Type: display, body, label, number and button fonts; label case and spacing.
  • Shape: border width, corner sizes, shadows, how hover lifts.
  • Flavour: the icon set, pixel art, which moments animate and how.
  • Not allowed: moving, hiding or adding things; changing behaviour or words. That would be a UX change.

Making a new style later

  1. Copy the style template.
  2. Fill every contract token: colours (dark and light), fonts, border, corners, shadows, number colour, highlight colours.
  3. Add skin rules if you want them, such as offset shadows or uppercase labels.
  4. Make the icon set in the new look, or keep the pixel icons.
  5. Run the checklist: contrast in both themes, all three widths, every state on this board.
  6. Point a project at it with one line. The UX needs no changes.

Patterns for complex data

The answers to "too many sections, dropdowns and menus". Each one is a UX rule, so it works with any style. All of them are live in the demo above.

Briefing overview

  • Top to bottom: setup (until done), what changed, key numbers, activity, sections at a glance.
  • Every key number has a sparkline and a comparison with the previous period.
  • Each section tile shows its one headline and opens the section.

Inspector drawer

  • Click any row, cell or chart point to open its detail from the right; the page stays where it was.
  • Back arrow when one drawer leads to another; ‹ › steps through neighbours.
  • Bottom sheet on a phone.

Rule bar and sentences

  • Applied rules sit in a tinted bar above the data, never inside a collapsed section.
  • Each rule reads as a sentence of tokens: did level_start where level = 12.
  • AND/OR is a visible button between rules; the match count is always shown.

Rule editor

  • Opens in a drawer, not inline, so it can't blend into the page.
  • Groups are coloured blocks by depth, with an explicit all/any switch.
  • "Reads as" repeats the rule in plain words; the live preview counts matches as you type.

Highlights bar

  • Each highlight is a coloured chip with its match count, an on/off eye and edit.
  • Quick presets sit next to "+ Highlight".
  • A map shows where matches fall; Previous/Next jumps between them; "Only matches" filters.

Funnel

  • Headline first: one big conversion number in a sentence.
  • Steps are a numbered list of sentences; options are chips that light up when changed.
  • Between bars: players lost, share and median time, with "See who"; the biggest drop is marked.

Curve plus heat strip

  • For anything level-by-level: a "players remaining" curve shows the shape at once.
  • The two steepest drops are labelled; a heat strip gives every level one cell.
  • The table below holds the exact numbers.

Nothing hidden changes the numbers

  • Any active filter, rule, option or highlight is visible as a chip or bar.
  • Segmented buttons for up to 4 options, dropdowns only for long lists.
  • Labels with a dotted underline explain how the number is counted.

Getting around and staying informed

  • Ctrl/Cmd + K jumps to any page, game or action.
  • The link button copies a URL that reopens this exact view.
  • The bell keeps every toast; each panel shows when it was updated, with optional auto-refresh.

Undo, or type to confirm

  • Reversible actions just happen, with Undo in the toast.
  • Permanent ones open a dialog listing what's lost and ask you to type the name.
  • Try both in Manage → Game settings.

Setup checklist

  • Each new game gets the steps that make its data trustworthy.
  • Uses Done → Verified, so "imported" and "checked" are different states.
  • Collapses when you're done with it; it disappears once every step is verified.

NutBot, in every AVN tool

One assistant pattern for the whole family. Each app gives it that app's tools, and it answers with that app's own tables, charts, timelines and checklists. Try it in the demo: the NutBot button, Ctrl/Cmd + J, or type a question into Ctrl/Cmd + K. Open a player first to ask about them.

Where it lives

  • A panel on the right; the page stays usable next to it, and an open drawer slides over to make room.
  • Bottom sheet on a phone.
  • Open with the NutBot button or Ctrl/Cmd + J, or ask straight from Ctrl/Cmd + K.

It shows what it's looking at

  • "Looking at" chips: game, page, range, version, the open player or session.
  • Tap × to leave something out; answers say which filters they used.
  • Suggested questions change with the page.

It shows its work

  • Each tool call appears as it runs: name, inputs, a check when done.
  • Folds to "Used 2 tools" afterwards; open it to audit.
  • Numbers link to the view they came from ("Open timeline", "Open level 12").

Answers use the app's components

  • Text plus blocks: table, chart, timeline, checklist (Done / Verified), funnel steps, link buttons.
  • Same tokens as the page, so they change with the style.
  • Any answer can be pinned to Overview as a tile.

It asks before it changes things

  • Reading runs freely. Saving a funnel, adding a highlight or rule, or changing settings appears as a proposal card with a preview.
  • Nothing happens until you press the button; Undo follows in the toast.
  • Permanent actions are never offered.

It's honest

  • Says when data is missing ("gdpr_applies was never logged") instead of guessing.
  • Mentions small samples and the range it used.
  • Asks back when the question is ambiguous ("Which player?").

Rules for the flavour

  • Homage, never copies: no logos, characters, names or quotes from games and films. Shapes, colours and moods only.
  • Flavour lives in moments: empty states, boot, success, palette names, the server page. Never inside tables or numbers.
  • One motif per screen, at most.
  • Dora, the nut and NutBot are yours, so they can appear by name.

Icons

Built on PlayLens's icon: a 10 × 10 pixel tile, warm dark ground, a one-pixel frame, one cream idea inside and a single spark pixel. Every AVN tool gets one in the same grammar. Hover an icon to see it twinkle; click to rebuild it.

The spark is a status light

Grammar for a new icon

  • Grid: 10 × 10, crisp edges, no smoothing. It has to read at 16 px.
  • Ground: the warm dark tile in every theme, so the tab icon never changes with light mode.
  • Frame: the same one-pixel rounded square, corners left open.
  • Inside: one idea in cream, six pixels or fewer.
  • Spark: one accent pixel outside the frame, placed where it hints the verb. PlayLens's is the lens handle (inspect); Analytics' sits top-right, where growth goes (measure).
  • Export: 16, 32, 180 (Apple touch icon) and 512 px from the same SVG.

Motion budget

  • Plays once per event, never on a timer.
  • Loops only for live things: the live dot, packets on a live pipeline, an error spark. They stop when data stops.
  • Under 1 s, except the boot (1.3 s, once a day).

  • Scenes only in empty states, at most one per screen.
  • Everything off with reduced motion; the final state shows straight away.

Pickers

Three controls for choosing values, all live in the demo above. They share one popover so they feel like one family.

Multi-select list · Filters

For combining values from one or more categories: environment, version, platform.

  • Categories get a label with a thin rule.
  • Checkbox on the left, count on the right.
  • The common default sits on top as a toggle.
  • Applied values show as chips under the bar, each removable.
  • Clear and Done in the footer.

Single-select list · Range preset

For picking one of a few options: date presets, sort order, platform.

  • Same rows, no checkboxes.
  • A tick marks the current choice and the text goes bold.
  • The right-hand slot holds a hint instead of a count, such as the date span.
  • Picking an option applies it and closes the list.

Date range · Calendar

Opens from the date field or from "Custom range".

  • Two taps: start, then end. It applies on the second tap.
  • The range is filled softly, the ends are solid, today has a ring.
  • Weeks start on Monday; neighbouring months are dimmed.
  • Arrows move month by month.

All three open under their control on desktop and tablet (at most 460 px tall, scrolling inside). On a phone they become a bottom sheet with 44 to 46 px rows. Esc or a tap outside closes them, and every row is a real button, so they work by keyboard.

Data patterns

Two more patterns from Analytics that carry over to every tool.

Change cell · comparing two things

  • The arrow shows which way the number moved.
  • The colour shows whether that is good or bad. Less drop is good, so it is green even though the number fell.
  • The last words say it out loud, so nothing depends on colour alone.
  • Units sit after the value (pp = percentage points).

Status card · one per game

  • Who it is: icon, name, package id.
  • Where it runs: a pill per platform with its total; a dashed pill invites adding the other one.
  • How it is doing now: today's number against yesterday's.
  • How fresh the data is: event total and last event time. A tag says Live or Quiet.
  • The whole card is one link; the arrow nudges on hover.

Toasts · bottom right

New toasts take the bottom slot and push the older ones up. Success and info fade on their own (a thin line shows the time left), warnings stay a little longer, errors stay until dismissed. Hover to pause.

Loading rules

  • Under 300 ms: show nothing. A flash of skeleton is worse than a short wait.
  • 300 ms to 1 s: skeleton only, with the same shape as the content so nothing jumps.
  • Over 1 s: skeleton plus one status line: spinner, what is happening, seconds elapsed.
  • Over 10 s: the line says it is taking longer than usual and offers Retry. Never spin forever.
  • Refreshing what is already on screen: keep it visible and say "Refreshing…" in the header. Never blank a page that has data.
  • Buttons: spinner replaces the icon, the label says what is happening ("Preparing…"), the button is disabled and keeps its width.
  • Spinners are for buttons and one-line status. Skeletons are for content.

Toast rules

  • Bottom right. The newest toast takes the bottom slot; older ones slide up. On a phone they span the width.
  • At most 4 visible. When a fifth arrives, the oldest non-error leaves.
  • Timing: success and info 5 s, warning 8 s, error until dismissed. Hover or focus pauses the timer.
  • Always dismissible with the × button.
  • Same message twice becomes one toast with ×2 and a fresh timer.
  • One action at most, a verb: Retry, Download, Undo.
  • Use a toast for the result of something the person just did, or news from outside. Not for things already visible on the page.
  • Screen readers hear toasts politely; errors interrupt.

Every error says what happened, whether the data is safe, and what to do next. No "Something went wrong". Never the browser's alert box. One failure gets one message: an inline error or a toast, not both. If stale data exists, keep it on screen under a banner.

Status and tags

A small vocabulary, each kind with one meaning. "Done" and "Verified" are separate on purpose: something can be finished without anyone having confirmed it yet.

The kinds

VerifiedConfirmed by a check or by real data
DoneFinished, but not confirmed yet
SyncingNeutral news, or something running now
BetaNew or experimental feature
WarningMight be wrong; needs a look
FailedBroken or blocking
CurrentThe selected or current thing
InactiveIdle, archived, replay, no data

Two steps: done, then verified

Not started→Done→Verified
  • SDK added to the game: Done. First event arrives: Verified.
  • Release uploaded: Done. Players on that version seen: Verified.
  • Dictionary imported: Done. Events match their descriptions: Verified.

Verified is only ever set by a check, never by hand. The Data health pipeline in the demo shows both: three steps verified, one waiting for confirmation.

Styles · same kinds, three weights

Counts12431Soft is the default. Use outline inside dense tables and dot when a status sits next to a name. Always a word, never colour alone. At most two kinds in one row.

Dense data

People using these tools compare many numbers at once, so the layout should give data the room and everything else as little as possible. See it in the demo: Levels → Compare releases, then flip Roomy and Compact.

Give the data the room

  • Use the width. Data pages have no maximum width. Only paragraphs are capped, at about 65 characters.
  • Data starts on the first screen. Explanations become a one-line footnote or a tooltip, never paragraphs above the table.
  • One toolbar line. Selectors, filters and actions share a row and wrap only when they must.
  • The table uses the height. Sticky headers, scroll inside the data only, and about 20 rows visible on a laptop in Compact.
  • Summarise above, detail below. "9 worse · 4 better · 11 unchanged" in one line, then the table.

Say each thing once

  • Two densities. Roomy for reading, Compact (about 28 px rows) for comparing. The choice is remembered.
  • Don't repeat words per row. A ◦ marker plus one legend line replaces "small sample" on every row.
  • Combine value and count in one cell: 14.3% · 1.
  • Group columns under spanning headers (0.1.2 · A, 0.1.3 · B) and keep the first column pinned when scrolling sideways.
  • Tint only what matters, such as changes of 5 pp or more. Everything else stays neutral.
  • Numbers are right-aligned, monospaced, tabular. On a phone, scroll sideways and don't hide data.

Always short, always meaning something. All of it switches off for people who ask for reduced motion.

Grow from the baseline, staggered

Hover
Colour and a 2 px icon nudge, nothing bouncing
Tables & text
Never animated after they appear
Charts on resize
Redraw without replaying the grow animation
Everything else

Rules

Keep it calm

  • One accent job per screen area: the main button, the active item, the highlighted data point. Nothing else is orange.
  • Status colours mean state only (green, amber, red), never decoration.
  • Pixelify only for page titles and key numbers. Tables, forms and body text use the plain fonts.
  • Counts in the sidebar only when something needs a look; no status line under every item.

Keep it usable

  • Account and admin pages (workspaces, team, status, settings) live in the account menu, not the main list.
  • Every touch target is at least 44 px on phone; the tab bar and sheet rows follow this.
  • Every state has a word as well as a colour, so it reads without colour.
  • Every page works at all three widths before it is called done.
